# 探索幣

教師工作室嘅「任務探索幣設定」會逐任務儲存 Firestore `coinRules/{taskId}`。可停用、固定金額、按正式成績或完成程度設定最多 20 級獎勵；只取符合嘅最高門檻。金額係 0–100,000 整數，唔會用原有成績 × 1.28。

## 結算政策

- 新學生冇帳簿項目時餘額為 0；唔會重設任何現有餘額。不同任務嘅正數獎勵會累積。
- 未設規則、停用、未達門檻、固定或分級結果為 0 都唔會建立結算項目，亦唔會鎖定日後資格。每人每任務只派一次正數獎勵；首次指首先成功確認嘅正數入帳交易，唔係最早提交日期或最高分。
- 選擇題喺老師工作室核算時結算；短答要全部批改完成先結算。提交時嘅暫存零分唔會發幣，正式零分可以按規則結算。
- 遊戲由老師喺「學生遊戲場次與錯題庫」選擇玩家後按「確認本局探索幣」。已完成且至少作答一次先有效；成績為答對次數除以作答次數嘅百分比，四捨五入。呢個明確教師確認係遊戲嘅核准步驟，唔會單憑學生聲稱完成即發幣。
- 完成程度現時只有完成後 100%，未完成唔派幣。完成程度分級只會用 100 去選最高符合門檻，唔會觸發 50% 或 80% 嘅部分完成獎勵；需要按表現分級應選「正式成績」。
- 重做、重複提交、交易重試、同時批改、再次確認遊戲、改分及改規則都唔會追加或扣回已結算金額。試卷同遊戲共用同一個任務結算鍵。
- 舊有零幣項目可由教師交易喺首次符合正數獎勵時原位轉成正數，唔使清空帳戶或批量刪除紀錄。已有正數項目保持不變，今次冇實作重做補差額。
- 教師工作室載入／重新整理會重新檢查已載入嘅正式成績是否符合首次正數獎勵，保留原成績及評語。儲存批改亦會檢查；未載入舊提交要先載入更多。遊戲則由老師再次按「確認本局探索幣」。單純改規則唔會即時掃描全部學生派幣，確認時使用當時規則。

## 持久化及權限

`coinAccounts/{studentId}/entries/{taskId}` 保存來源提交／場次、金額、分數、規則快照及伺服器時間。正數項目不可修改或刪除；唯一更新例外係教師將歷史 0 幣項目轉為有有效來源嘅正數獎勵。批改及入帳同一個 Firestore transaction；遊戲結算亦用 transaction。學生餘額即時加總自己帳簿嘅 `amount`，唔依賴本機快取成績。冇登入顯示破折號，讀取失敗會顯示「未能讀取」。

Firestore 規則只容許既有教師身份管理規則及新增有有效來源嘅正數結算；學生只能讀取自己帳簿，唔可以直接發幣、升級零幣紀錄或改餘額。教師身份沿用專案既有單一管理員規則。新零幣寫入亦會被規則拒絕。

餘額係帳簿金額總和，可供日後加入負數扣款項目。今次冇商店亦冇開放扣款 API／規則；未來需獨立兌換 ID、受信任交易、防超支及相應規則，毋須改寫既有獎勵紀錄。

## 已接通遊戲

目前 registry 只有 `cold-war-maze`（冷戰・地下間諜），對應 `S5_ColdWar_Maze`。版本題庫包含選擇、排序、配對、分類及改錯題；每次完整答案與標準答案完全一致先計答對一次，冇局部配分。同一題重答每次都計入總作答次數。派幣成績為 `round(100 × correct / attempts)`，唔係遊戲內文件數、通關時間或其他畫面分數。

探索館嘅 `ConnectedGame` / `GameSyncContext` 接收遊戲事件，`submitGameEvent` 保存並核對答案，待完成事件及所有作答同步後才成為已完成場次。教師頁 `GameRecords` 選玩家後嘅「確認本局探索幣」呼叫 `confirmGameCoins`。未完成、放棄、零作答場次不派幣。只有 iframe／外部遊戲連結、未接通此事件及版本題庫流程嘅遊戲，暫時不能自動計分派幣；今次冇新增遊戲整合。
