# 探索幣

教師工作室嘅「任務探索幣設定」會逐任務儲存 Firestore `coinRules/{taskId}`。可停用、固定金額、按正式成績或完成程度設定最多 20 級獎勵；只取符合嘅最高門檻。金額係 0–100,000 整數，唔會用原有成績 × 1.28。

## 結算政策

- 預設未設定為零幣。每名學生每項任務首次有效結算一次，包括零幣結算。首次指首先成功確認嘅交易，唔係最早提交日期或最高分。
- 選擇題喺老師工作室核算時結算；短答要全部批改完成先結算。提交時嘅暫存零分唔會發幣，正式零分可以按規則結算。
- 遊戲由老師喺「學生遊戲場次與錯題庫」選擇玩家後按「確認本局探索幣」。已完成且至少作答一次先有效；成績為答對次數除以作答次數嘅百分比，四捨五入。呢個明確教師確認係遊戲嘅核准步驟，唔會單憑學生聲稱完成即發幣。
- 完成程度現時只有完成後 100%；保留分級依據俾未來擴展，唔會虛構部分完成數字。
- 重做、重複提交、交易重試、同時批改、再次確認遊戲、改分及改規則都唔會追加或扣回已結算金額。試卷同遊戲共用同一個任務結算鍵。
- 舊有已批改試卷唔自動補發，改舊成績亦唔補發；舊遊戲只會喺老師明確按確認時結算。未結算嘅新有效批改採用確認當刻規則。

## 持久化及權限

`coinAccounts/{studentId}/entries/{taskId}` 係不可修改或刪除嘅帳簿項目，保存來源提交／場次、金額、分數、規則快照及伺服器時間。批改及入帳同一個 Firestore transaction；遊戲結算亦用 transaction。學生餘額即時加總自己帳簿嘅 `amount`，唔依賴本機快取成績。冇登入顯示破折號，讀取失敗會顯示「未能讀取」。

Firestore 規則只容許既有教師身份管理規則及新增有有效來源嘅結算；學生只能讀取自己帳簿，唔可以直接發幣或改餘額。教師身份沿用專案既有單一管理員規則。未設定規則亦會寫入零幣項目作結算記錄。

餘額係帳簿金額總和，可供日後加入負數扣款項目。今次冇商店亦冇開放扣款 API／規則；未來需獨立兌換 ID、受信任交易、防超支及相應規則，毋須改寫既有獎勵紀錄。

## 驗證及發布

已用本機 Firestore 模擬器測試真實持久化、權限、並發、短答批改、遊戲答對率、零幣鎖定。測試檔：`scripts/coins.integration.test.ts`；設定：`vitest.coins.config.ts`，預期模擬器喺 `127.0.0.1:8080`，專案 ID `demo-coins`。單元測試：`client/src/lib/coinModel.test.ts`。

本次未部署正式網站或 Firestore 規則。日後發布必須先發布本專案 `firestore.rules`，再發布前端；正式舊規則未更新前，新帳簿及設定存取會被拒絕。老師應先設定獎勵，再確認新成績／遊戲。前端預覽只驗證介面，唔會冒充真實餘額或寫入正式資料。

本機學生預覽：`http://localhost:3000/__home-demo?view=cards&class=S5`。
本機教師設定預覽：`http://localhost:3000/__home-demo?view=cards&class=S5&coins=teacher`。
