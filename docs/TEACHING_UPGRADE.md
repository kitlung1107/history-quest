# 教學後台升級與使用

Google 成績服務已於 **2026-09-24** 升級至 **2.1.0（API v2、Apps Script 部署第 3 版）**，保留原 `/exec` 網址及教師 PIN。原有 3 筆成績可讀取，4 個公開任務已同步。網站改動仍由你自行 commit／push。

升級前已用獨立、全部為虛構資料的 Google 試算表驗證交卷、重試去重、PIN 保護、短答批改、評語查閱、名冊及舊網站相容；22 項本機測試亦通過。以下首次設定步驟供新專案或日後重建參考，現有正式服務不必重做。

正式 API 的 GET／POST 及瀏覽器跨網域連線已驗證。網站為每次請求加入獨立識別值，避免重用 Google 的暫存重新導向網址；未登入查詢及重複錯誤 PIN 均會拒絕。

## 八項功能

| 功能           | 入口與操作                                                                                                      |
| -------------- | --------------------------------------------------------------------------------------------------------------- |
| 多題測驗       | CMS → 歷史任務 → 測驗題目；加入 1–30 題選擇題或文字短答，拖動排序、設定每題分數及解說                           |
| 答案收集箱     | 教師後台 → 答案收集箱 → 查閱／批改；每次重做均保留獨立紀錄                                                      |
| 篩選與匯出     | 按任務、班別、姓名／學號、香港日期、批改狀態篩選，匯出成績或逐題答案 CSV                                        |
| 複製任務       | CMS 任務選單 → Duplicate／複製；副本首次儲存會加上獨立識別碼並隱藏，檢查後再開啟公開顯示                        |
| 名單與欠交     | 教師後台 → 班級名單與欠交；下載 CSV 範本、匯入、檢查後確認；選任務及班別查看欠交                                |
| 短答批改與評語 | 收集箱為每題短答填分及評語，可加總評；學生由「我的提交與評語」查閱                                              |
| 發佈前預覽     | CMS 編輯網站首頁或任務時，按表單頂部「開啟學生畫面預覽」，可切換 390px 手機寬度；未存檔內容即時送到學生版面試看 |
| 圖片素材目錄   | CMS → 圖片素材目錄；分類、標籤、描述、來源／授權及圖片；任務圖片欄可重用相同檔案或連結                          |

新任務第一次儲存也會加上識別碼後綴並保持隱藏。已有任務的識別碼不會自動改動；不要手動改它，否則舊成績不再對應。題目識別碼在同一任務內不可重複。

預覽只把**目前正在編輯的一份**首頁設定或任務草稿套入網站，其他教材仍為目前建置版本。預覽不會儲存學生資料或提交成績；不提供整批未儲存變更的聯合預覽。Google Drive 功課檔案上載不在這八項功能內。

## Google 服務首次設定

1. 先在私人位置備份現有 Apps Script 程式，另建空白試算表，以虛構資料作測試。不要將真實學生資料或 PIN 放入 GitHub。
2. 建立測試 Apps Script 專案，貼上本儲存庫的 `apps-script/TeachingService.gs`。使用 V8 執行環境。舊的 `doGet`／`doPost` 不可與新版同名函式並存。
3. 在 Apps Script「專案設定 → 指令碼屬性」新增：
   - `HQ_SPREADSHEET_ID`：測試試算表網址 `/d/` 與 `/edit` 之間的 ID。
   - `HQ_PIN_SHA256`：6–12 位數字教師 PIN 的 SHA-256 十六進位值。可在本機執行 `node scripts/hash-teacher-pin.mjs`，輸入時不顯示 PIN；複製輸出的雜湊值到此屬性。不要把 PIN 放入網站設定。
   - `HQ_PIN_SALT`：只供遷移已加鹽的舊 PIN，驗證值為 SHA-256(`salt + PIN`)。本專案已保留原設定；全新設定可不填此屬性。
4. 部署為網頁應用程式：執行身分為試算表擁有人；存取設定須允許網站學生請求（通常為「所有人」，實際選項受學校網域管理設定限制）。資料讀取與批改仍由程式驗證 PIN／提交查閱碼。
5. 複製部署 `/exec` 網址。在本機未追蹤的 `.env.local` 設定 `VITE_GAS_WEB_APP_URL=測試部署網址`，重新啟動開發伺服器。此網址不是秘密，但不要把教師 PIN 放在任何 `VITE_` 變數。
6. 在教師後台登入，按「同步題目設定」，才開始測試學生提交。這一步將目前公開任務的題目與配分送到成績服務，由服務重新核算選擇題分數。
7. 用虛構學生測試：多題提交 → 收集箱查答案 → 批改短答 → 用提交查閱碼讀評語 → 匯入測試名單 → 欠交與 CSV 匯出。刷新頁面確認資料仍存在。

## 正式切換

測試通過後，在短暫暫停學生使用的時段升級原有成績 Apps Script，設定**正式試算表 ID**及 PIN 雜湊，並在「管理部署」將原部署更新至新版本，保留原 `/exec` 網址。若改用新部署網址，須相應更新網站建置時的 `VITE_GAS_WEB_APP_URL`（或 `historyQuest.ts` 的預設網址）。

自行 commit／push 網站，等待 GitHub Actions 發佈完成。重新整理正式教師後台，再按「同步題目設定」。2.1.0 保留舊網站的成績提交及 PIN 保護的查詢接口，舊分數標示為「舊紀錄」；新版網站才提供逐題答案、短答批改及名冊介面。

僅 push 網站並不會升級 Google 程式。如果 Google 仍是舊版，新答案會留在本機重試，不能視為老師已收到。這段時間請勿清除學生瀏覽器資料。若需回復，恢復 Apps Script 先前部署版本及相配的網站版本；不要刪除新產生的 `HQ_` 分頁。

## 儲存與日常操作

- GitHub：網站、公開教材、圖片目錄；Google 私人試算表：答案、名單、批改與評語。
- 新資料分別保存在 `HQ_submissions`、`HQ_catalogue`、`HQ_roster`。JSON 會分成多欄儲存以容納長短答。請透過後台操作，不要直接修改儲存欄位。
- 原任務分頁不改寫；如具備 `attempt_id`、`task_id`、`student_no`、`class_name`、`score` 表頭，會在後台顯示為舊紀錄。升級時已核對原程式及讀取 3 筆舊成績；原程式另備份於私人指令碼屬性 `HQ_BACKUP_V1_CODE_*`，原部署第 2 版可供回復。
- 每次新增、改題或改變公開任務範圍：CMS 儲存 → 等網站發佈 → 重整教師後台 → 同步題目設定。新舊題目版本不符的答案會保留本機並提示聯絡老師，不會套用錯誤答案表。
- 欠交按「班別＋學號」與所選任務比對任何已完成提交，待批改亦算已交。學號 `01` 與 `1` 不同，報到及名單要一致。CSV 匯入採合併，不刪除其他學生。
- 選擇題自動評分，短答未全部批改前整份總分留空；全部完成後依配分換算百分制。圖表平均只計已有分數的提交，重做亦計入。
- 學生查閱碼是一份提交的私人憑證，預設留在該瀏覽器，可自行複製保管；知道查閱碼的人可以看到該份答案與評語。跨裝置要貼上完整查閱碼。不要共用查閱碼。
- 目前學生身分仍是自行填寫班別／學號，並非學校帳戶認證；這是課堂練習工具，未提供正式考試防作弊。選擇題答案本來就在公開教材內。

## 本機檢查與安全示範

執行 `pnpm check`、`pnpm test:content`、`pnpm test:teaching`、`pnpm build`。本機 `pnpm dev` 後：

- `/admin?preview=teacher`：虛構教師資料，可試批改、匯入名單、欠交及匯出；不送 Google，正式建置不提供此登入捷徑。
- `/?preview=student`：學生頁面試看，試答不提交。
- CMS 首頁／任務預覽：同樣不提交。

Apps Script 測試使用模擬試算表，涵蓋驗證、計分、重試去重、批改衝突、名單合併、舊資料讀取及長答案。它不能代替實際 Google 帳戶授權、配額與跨網域連線測試。
