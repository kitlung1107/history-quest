# 收藏卡庫

教師工作室的「收藏卡庫管理」連至既有 Sveltia CMS → 收藏卡庫。權限沿用 GitHub 儲存庫編輯權限；學生的 Google 登入不授予 CMS 權限。

管理者可修改卡片名稱、2:3 無字底圖（建議 1024×1536）、排序及「可供學生選用」。永久識別碼建立後保持不變；新增卡片還須另行配合既有發卡模組及安全規則，單在 CMS 新增不會授予學生持有權。卡圖的上、下名牌分別顯示暱稱和姓名，由網站疊加文字，上載功能不會自動移除圖片中文字。

學生首次儲存角色後，角色保持固定；所有年級獲贈同角色新手卡，中一 `1A`–`1E` 班另獲贈同角色尼羅河卡。學生只能選擇已持有、同角色且已啟用的卡。未選、停用、已刪除或無權使用的卡不會自動替換成另一張卡，畫面保留學生姓名、暱稱及無卡提示。

學生在「更換卡片及暱稱」頁面選卡，卡片預覽即時切換，按「儲存卡片」後保存 `cardId`；返回首頁便顯示該卡的背景。重新載入或登入時，以帳戶保存的卡片重新解析背景。暱稱仍可修改，姓名、班別、學號不可由學生更改。`cardId` 與舊 `avatar` 分開，舊資料及既有持有權保持不變。

## 設定卡片對應的首頁背景

1. 在 CMS 選「首頁背景庫」→「背景圖片與名稱」，於「可重用背景」新增項目。填寫唯一、固定不變的「永久識別碼」（3–80 個英文字母、數字、底線或連字號）及「背景名稱」，再選擇「背景圖片」。圖片只需上載一次；已有圖片可直接從媒體庫重用。
2. 儲存背景庫後，到「收藏卡庫」→「收藏卡上載、排序與啟用」，展開一張現有卡，在「配對首頁背景」欄搜尋或選擇剛才的背景名稱。
3. 其他卡片選擇同一背景即可共用圖片。例如男、女版尼羅河卡可指向同一背景；更新該背景的圖片後，所有相連卡片會一起使用新圖。
4. 清空卡片的「配對首頁背景」欄，可回復使用「網站與首頁設定」→「網站與首頁區塊」內的「首頁預設背景（未配對時使用）」。保留背景識別碼；只改名稱不會影響已有配對。

背景資料存於 `client/src/content/settings/backgrounds.json` 的 `backgrounds` 清單，每項只有 `id`、`name`、`image`。卡片在既有 `cards.json` 內增加可選 `backgroundId`，不在每張卡複製圖片路徑。背景庫初始為空，既有卡片沒有新增配對；現有預設圖 `home-voyages-exchange-v2.webp` 保持不變。圖片素材目錄的教材分類、標籤、授權及使用位置功能全部保留；圖片使用索引同時列出背景庫項目及引用它的卡片。

現有預設圖為 2172×724，即 3:1 橫幅。首頁沿用圖片自然比例顯示；為維持目前背景區域高度，新背景宜同樣採用 3:1 比例，並保留中央館名文字所需的清晰空間。其他比例會令背景區域高度隨原圖改變，應先查看手機及桌面預覽。

沒有配對、空值（缺省、`null`、空字串或全空白）、找不到背景、卡片不可用或背景圖片載入失敗，都顯示既有預設首頁大圖。換卡後會重新嘗試對應圖片。配對只更換首頁圖片；館名中英文、文字配色、排版及取景位置不變。若預設圖片本身失效，仍需管理者修復該圖片。

這次功能不需要資料遷移，不改寫任何學生帳戶、卡片持有權、角色或安全規則；舊卡沒有 `backgroundId` 仍可使用。背景配對由卡庫內容解析，不另外寫入學生帳戶。CMS 內容沿用既有 GitHub 提交及 Pages 建置流程，要等經審核的版本發佈並載入後才會更新，並非 Firestore 即時背景庫。

## 本機預覽及驗證

本機 CMS 測試入口 `http://127.0.0.1:<port>/cms/index.html?test=1` 使用隔離的 `test-repo`，不寫入 GitHub。只有本機主機名支援此參數；正式管理入口不帶 `test` 參數。兩者使用同一份 `config.yml`。測試時先確認是隔離測試倉庫，再建立示例背景及卡片配對。

開發模式的 `/__role-preview` 提供本機展示帳戶，換卡、重新載入及「模擬重新登入」只使用 `localStorage`，不改動真實學生資料，也不等同已驗證真實 Google 登入。驗證需涵蓋多卡共用、清空／無效配對、舊卡、圖片載入失敗，以及手機和桌面版面。只使用既有圖片或隔離示例，未審批的製圖結果不會自動加入背景庫。

程式檢查：`pnpm run test:backgrounds`、`pnpm run test:cards`、`pnpm run test:content`、`pnpm run test:editor`、`pnpm run check` 及 `pnpm run build`。真實雲端登入及正式 CMS 發佈如未實際操作，須在交付時列為測試限制。本次工程先提供本機預覽與差異審核，由用戶自行 commit／push；不 stage、不 commit／push／deploy，也不在正式 CMS 儲存或發佈。
