# 收藏卡庫

教師工作室的「收藏卡庫管理」連至既有 Sveltia CMS → 收藏卡庫。權限沿用 GitHub 儲存庫編輯權限；學生的 Google 登入不授予 CMS 權限。

管理者可新增項目、上載2:3無字底圖（建議1024×1536）、改名稱、拖動排序、關閉「可供學生選用」或移除項目。識別碼必須唯一，建立後保持不變。首批圖片可作名牌位置模板：上方左側是暱稱，下方是班別(學號)姓名。上載功能不會自動移除圖片中文字。

CMS 發佈沿用現有 GitHub 提交與 Pages 建置流程；新版本載入後，學生能看到新卡庫。不是 Firestore 即時卡庫。已選停用或刪除卡的帳戶會顯示排序第一張啟用卡，不會改寫或刪除學生資料。全停用時顯示無卡提示及學生資料。

學生在「更換卡片」頁面選卡，預覽即時切換，按「儲存卡片」後保存。暱稱仍可修改，姓名班別學號不可由學生更改。cardId 與舊 avatar 分開，舊角色鍵和資料不刪除，不根據性別選卡。所有未選卡的帳戶使用相同預設卡。

部署前必須先由負責人部署本機 firestore.rules 的 cardId 相容規則，再發佈網站。此實作沒有部署任何規則或網站。舊規則不接受 cardId，若未先更新，雲端選卡儲存會被拒絕並顯示錯誤；本機示範只寫 localStorage。

本機 CMS 測試入口 `/cms/index.html?test=1` 使用 CMS 的 test-repo，不寫入 GitHub。正式管理入口不帶 test 參數。管理測試畫面與正式 CMS 使用同一份 config.yml。

驗證：`pnpm run test:cards`、`pnpm run check`、`pnpm run build`；Firestore 規則測試使用本機模擬器及 `scripts/cloud-rules.test.mjs`。卡圖載入失敗時顯示學生資料；名牌太窄時在卡下方補上完整文字，不改寫帳戶資料。
